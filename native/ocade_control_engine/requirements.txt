# OCADE control engine — Python dependencies.
#
# INSTALL PATH. OCADE runs this engine through the interpreter resolved in
# src/lib/agent/host-paths.node.ts, which is native/python-host/.venv. Install
# into that venv, not into a system Python:
#
#   native/python-host/.venv/Scripts/python -m pip install -r \
#     native/ocade_control_engine/requirements.txt
#
# There is deliberately no setup.py and no auto-installer. Nothing in this
# engine may install packages while it is running — see
# native/python-host/tests/test_engine_ships_safely.py for why, and for the
# test that keeps it that way.
#
# ── NO GOOGLE SDK ──────────────────────────────────────────────────────────
# `google-genai` and `google-generativeai` were here. Every module that used
# them now calls core/local_llm.py, which talks to Ollama on localhost.
#
# Removing the packages rather than only the call sites is the point: with no
# SDK installed there is no path back to a remote model by accident, and the
# one remaining importer — the standalone PyQt6 app in main.py / ui.py /
# dashboard/, which OCADE never starts — simply cannot run. That app is
# scheduled for deletion once ocade_bridge.py reaches capability parity with
# its tool table; until then it stays as reference and ships to nobody.
#
# ── THE LIST BELOW IS WHAT THE CODE ACTUALLY IMPORTS ───────────────────────
# It was out of sync: a dozen packages the engine imports were missing, so a
# clean machine installed "successfully" and then failed at the first feature
# that needed one.

# NO PLAYWRIGHT, AND IT MUST NOT COME BACK.
#
# `playwright` was listed here for actions/browser_control.py — a second
# browser stack that bypassed every guard in the Node managed-browser host.
# That module is deleted. The package is removed with it rather than left
# behind, because a stray `pip install -r` is all it would have taken to make
# the unguarded path importable again.
#
# Browser automation lives in native/browser-host/index.mjs and uses the Node
# playwright-core dependency. The Python engine does not drive a browser.

                         # needs a C compiler that a user machine will not have.

# --- the phone dashboard ----------------------------------------------------
# core/remote.py serves a mobile page over the local network and shows a
# pairing QR on the desktop. `qrcode` is pure Python with no build step and no
# runtime of its own — it turns a string into a matrix, and core/remote.py
# renders that matrix as inline SVG itself. The HTTP server is stdlib
# (`http.server`), NOT FastAPI: one page and one JSON endpoint do not need a
# framework, and the deleted PyQt app's fastapi/uvicorn pair is exactly the
# dependency weight this avoids bringing back.
qrcode
