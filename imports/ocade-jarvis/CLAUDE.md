# OCADE JARVIS Preservation and Working-Engine Rules

## First action

Run /ponytail ultra and /caveman ultra before every fresh, resumed, or compacted session.

Then read root AGENTS.md, root CLAUDE.md, PLAN.md, docs/MEMORY.md, this file, and the intake README.

## Immutable source

Never delete, rewrite, rename, format, lint-autofix, dependency-upgrade, or Ponytail-debloat the uploaded original JARVIS ZIP or the exact imports/ocade-jarvis/source-original/ snapshot.

These are source provenance.

## Working-engine rule

The extracted JARVIS source is the main engine foundation.

Create a working runtime under jarvis-runtime/ and preserve its meaningful original structure initially.

Do not treat the ZIP as a tiny donor library.

Inventory the whole source and then continue immediately into implementation.

Preserve essentially all useful capabilities unless the owner explicitly rejected active behavior or a security replacement is required.

## Explicit production replacements

Replace the active old GUI with the new OCADE JARVIS web UI.

Remove active customer API-key entry and active plaintext provider-key configuration from the working runtime after OCADE Online intelligence is connected.

Keep the generic plugin subsystem preserved but unused/customer-hidden.

Keep the legacy phone dashboard preserved but do not expose it as the final active remote architecture.

Keep PyAutoGUI/desktop-control modules preserved even when the first web mission cannot yet execute them.

## Web mission

The canonical route is /ocade-jarvis.

JARVIS is Online-only.

Browser control is the first deep capability.

Integrate Playwright/Playwright-MCP capability internally so users do not configure it.

Use semantic browser targeting before visual/coordinate fallback.

Re-observe after resize, zoom, reflow, scroll-context, navigation, and tab changes.

Never trust stale coordinates.

## Ponytail rule

Ponytail may simplify working production code after replacement behavior is proven.

Ponytail must never use LOC reduction as a reason to destroy source provenance or remove preserved capabilities.

The original ZIP and source-original snapshot are absolute deletion exclusions.
