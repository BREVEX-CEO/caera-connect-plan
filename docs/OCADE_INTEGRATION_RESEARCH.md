## 1. Summary

1. **The single biggest problem is still OCADE's loop, not a model or a missing library.** Three things combine:
   - Planning runs synchronously inside the device's HTTP request (`authority.server.ts:256,1072,1088,1094`).
   - Every mutation costs its own model turn (`planner.server.ts:1352-1366`).
   - The desktop is observed only on request, with no element references, no change-only snapshots and no obstacle reporting.
2. **The 41 repositories cover almost every missing capability.** Of the 24 capabilities OCADE needs (§3), 22 have a usable external implementation to reuse, port or follow (92%). The two without one are OCADE's own safety core: the authority/lease/effect fence and the allowlisted model route. No repository has an equal for them, so they stay. This is a capability count, not a share of lines of code.
3. **Desktop layer: use cua-driver (MIT, Rust, MCP over stdio) as the primary driver** behind an OCADE adapter, gated on the existing hosted Windows and macOS test ladders. Port surfaces and dialog detection from agent-desktop and mcp-windows.
4. **Gemma 4 31B: what can and cannot be made faster.**
   - Provider-side and out of OCADE's control: time to first byte (over 25 s observed), the 16,000 input-tokens-per-minute free tier, and no listed context caching.
   - OCADE-side and under its control: number of calls, input tokens, thinking tokens, coupling to the device request, retries and replay.
   - §5 gives concrete changes and acceptance targets.
5. **Two models only.**
   - Gemini 3.5 Flash-Lite is the recommended interactive model, based on vendor capability facts.
   - Gemma 4 31B is the second model: the alternative for a whole task, chosen at task start.
   - One model per task, with no mid-task switching. Neither model is proven on OCADE's tasks: 0/24 so far.

**Duplicates and conflicts resolved:**

- **Element references:** cua-driver, agent-desktop, mcp-windows, windows-mcp-server and UFO all provide them. Only one driver ships: cua-driver, because its effect contract maps directly onto OCADE receipts and it covers three OSes. The rest supply rules (C4–C7), not code.
- **Batching:** UFO and mcp-windows overlap. OCADE adopts mcp-windows' precondition fields plus UFO's stop-at-first-failure loop.
- **Replay:** OpenAdapt and CUAWright overlap. OpenAdapt's halting semantics win because they match OCADE's effect fence.
- **Web:** Playwright stays the engine. browser-use, Stagehand and Midscene contribute patterns only.

### 6.2 Workload assignment

The rule: one model per task. The model is chosen at task start and never switched mid-task. There is no repair escalation to the other model. This is what "no hybrid" means here.

**[inference]: to be confirmed by the §8 runs.**

| -------------------------------------------------------------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |

**Can either model reliably handle complex computer-use tasks?** There is no evidence on OCADE: 0/24. Vendor evidence:

- Flash-Lite 74.0% OSWorld-Verified.
- 3.5 Flash 5/25 full solves on expert KiCad.

So simple and medium GUI tasks are plausible, and expert multi-app tasks are not reliable through the GUI alone [inference]. This is why the plan routes professional apps through scripting and verifies independently.

## 7. Unified architecture

```
Website (Realtime subscription; replaces 2 s polling)
 └─ Authority (Supabase; unchanged: tasks, turn lease, permits, grants, STOP, journal)
     ├─ Device receipt / claim  ── records, enqueues plan(task), returns < 2 s
     └─ Cloudflare Queue consumer (15 min wall)  [G1]
          ├─ Procedure library: matching verified procedure?  ── replay steps [G9]
          └─ Planner turn: one model per task (Flash-Lite default | Gemma 31B)
               input:  goal + compressed history [G5] + piggybacked diff [G3]
               output: guarded batch of 1..N steps with leases + preconditions [G2]
               thinking: minimal (steps) | high (compile/repair) [G6]
               pacing: per (slot, model) token bucket [G8]
          └─ writes steps, nudges device
Companion (Python; gateway, sandbox, receipts, verify unchanged)
 ├─ Adapter worker (OCADE-owned, pinned)  ── cua-driver binary (pinned, stdio) [C1–C3]
 │     lease check (pid + handle + start time) before every call
 │     effect mapping: confirmed → observed; refused → not_applied;
 │                     partial | unverifiable | suspected_noop → unknown (FENCE)
 │     foreground delivery only with the person's grant; otherwise refuse
 ├─ Surfaces/dialogs reported as leasable windows in each observation [C4]
 ├─ Change-only snapshots + refs [C5]; event-assisted waits [C6]; UAC detection [C7]
 ├─ Batch executor: in order, stop at the first refusal/unknown/precondition miss [C8]
 ├─ Web: Playwright aria refs [C13], local action cache [C14], idle rules [C15]
 ├─ Scripted routes for Office/CAD/3D/video [C19]
 └─ Vision fallback: model image input on capture-bound regions [C16]
Verifier (independent; rubric pattern [C17]; narrated evidence [C18]) ── done | repair turn (same model)
```

## 9. Expected advantages, disadvantages and remaining limitations

**Expected advantages [inference until P1–P10 measure them]:**

- no request-bound timeouts
- fewer model calls (batches, piggyback, replay)
- fewer tokens (diffs, refs, compression)
- dialogs answered instead of stalling
- no focus theft
- one cross-platform driver plus Linux
- professional apps driven through scripting
- near-zero model cost for repeated tasks

**Disadvantages:**

- a third-party binary in the installer (signing, updates, supply chain)
- an adapter to maintain against a 0.x driver
- ports from C# and TypeScript sources need their own tests
- the queue adds some latency per turn (unmeasured)
- free-plan limits: Worker CPU 10 ms per invocation, 10,000 Queue operations per day [doc]
- a procedure library adds a table and a lifecycle

**Remaining limitations:**

- time to first byte, per-project quota and caching for Gemma stay provider-side
- GTK/VCL and custom-drawn apps stay hard (the driver refuses rather than solves; foreground mode needs the person's grant)
- expert multi-app GUI work is unproven for both models
- hosted runners are not consumer PCs (A2 governs the owner's PC)
- OmniParser v3 weight provenance is unverified
- the Playwright AI-snapshot Python API is unverified
