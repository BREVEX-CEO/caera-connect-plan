## Failures

- **F1 (Minor)** — row 4. The Offline engine is prepared and warmed in a browser whose offline allowance was refused (device limit): a model download and CPU spent on a browser that cannot answer offline. Evidence: preview tab console shows the engine loading after the first keystroke while `register_browser_device_for_current_user` answers 400 (device cap).
- **F3 (test only)** — row 1. `offline-turns-reach-the-account` waited a fixed 20 ms for an encrypted IndexedDB write; under load (training running) the simulated restart read an empty journal. Product writes are queued correctly; the test now waits for the record itself. Full suite then 1194 passed under the same load. Runtime 146 passed, 4 skipped; npm audit and pip-audit clean.
- **F4 (Minor)** — row 2. The admin journey saw React error #418 (server and client HTML differ during hydration) on `admin.localhost/auth/challenge?next=/admin`, after the second-factor step on the console origin. Seen once before (2026-10-01) without a URL; now located. The other 20 journeys passed. To reproduce with a development build in the fix wave.
- **F2 (Major)** — row 5. JARVIS does not know the person's devices: asked "which of my devices are connected right now?" it answered that it has no list and is "operating directly on this computer" (untrue: it runs in OCADE, and the account has DESKTOP-7CF9G0F and an audit device, both offline). The planner is not given device state, so status answers about devices are invented.
- **F5 (test only)** — row 6. `manual_installed_lifecycle.py` sent "exit" with the token from the real `~/.ocade_jarvis` instead of the temporary home it gave the installed agent, so "Exit ends it" and the two rollback checks after it failed (25/28). The product was right (the uninstaller, which runs with the agent's own home, stopped it). The test now uses the agent's home: 28/28.
- **F6 (Minor)** — row 17. On Android, Wake Mode can be turned on while notifications are not allowed; the microphone service then runs with its "OCADE is listening" notice and its Turn off action hidden (Android shows only its own microphone indicator). Turning Wake Mode on should ask for notifications too, through Android's own dialog.
- **F7 (Minor)** — rows 12–14. `app_info` lists "scripting" folders for programs that live in shared folders: Steps Recorder, Magnify and iSCSI Initiator (System32) were given Printing_Admin_Scripts, driver `.inf` folders, WebView extensions and licensing manifests; Skype for Business (Office16) was given Excel's Python code folder. The model is told about automation surfaces that have nothing to do with the app.
- **F8 (Minor)** — rows 12–14. For a Store package holding several apps, `app_info` reports the first program in the package, not the one launched: "Files" (`Microsoft.M365Companions_…!Files`) was reported as `People\PeopleLauncher.exe`. Its version, automation and file types are then the wrong app's.

- **F9 (Minor, production configuration)** — the OCADE verification email (read through Gmail: from auth@ocade.in, delivered, 8-digit code, readable) has the subject "Your sign-in link" although it carries a code, and says neither what it is for, how long it lasts (the project's email code expiry is 3600 s) nor what to do if it was not asked for. Sign-in and "Confirm it's you" share Supabase's "Magic link or OTP" template, which lives in the Supabase dashboard: changing it is an owner decision.
- **F10 (Minor)** — production Edge Function logs: every browser CORS preflight was recorded as a successful generation served by no key slot, inflating the health numbers. Fixed: a preflight leaves no record (regression in `edge-handler.test.ts`); needs the Edge Function redeployed with the release.
- **F11 (Major, also live in production)** — Google sign-in with a destination (`/auth?next=…`, used by device connection links, JARVIS and the consoles) put `?next=` on the OAuth callback. Supabase returns only to an allow-listed callback, matched exactly, so the person landed on the Site URL with an unused code and was not signed in (seen on the preview, which returned to `ocade.in/?code=…`). Fixed: the destination stays in the tab; the stand-in Supabase now matches redirects like Supabase, and the existing journey check failed on the old code and passes on the new.
- **F4 (resolved)** — root cause: an `ssr: false` route's client-side check redirected to the second-factor page while React was still hydrating (about half of admin journey runs). The signed-in layout's check now waits for the root's first commit; 8 of 8 admin journey runs clean.
- **F12 (Major, test isolation)** — running the runtime test suite on a computer with OCADE installed deleted the real login entry and told the real installed agent to exit (shared single-instance port and the real home's exit token). Fixed with a `conftest.py`; the suite then ran beside the installed agent with no effect on it.
- **F13 (Major, usage)** — an invalid action came back to the model only as "not valid", so it retried blind; on the preview about 15 billed uses passed with nothing done. Fixed: the validation reason is returned, and three invalid or refused calls in a row end the turn (and the background loop) for the person.
- **F14 (Major)** — Excel holds one workbook per file name: with another workbook of the same name open, Excel's Open returned nothing and every later edit failed with a null-object error. Fixed: the job uses an Excel of its own on a name clash and fails clearly if the workbook still cannot open.
- **F15 (Major, data safety)** — asked to keep the original, JARVIS edited `quarterly-sales.xlsx` and then copied it (undo kept a copy). Fixed: a workbook or document the person already has is changed only in a copy JARVIS made unless the person asked to change it (`overwrite: true`).
- **F16 (Major, result quality)** — JARVIS's totals row summed itself (`C6 = SUM(B6:E6)`) and the read-back said only "0". Fixed: edits report cells that refer to themselves or show an error value, and the rules tell JARVIS to fix them before finishing.
- **F2b** — asked which devices were connected, JARVIS listed disk drives. Fixed: device questions are answered from OCADE's device list without a task or a tool (to verify on the preview with a real turn).
- **F17 (Major)** — a start while the agent was running (login entry, Start menu, installer) counted as a failed start of the running build; three rolled a good build back, and the installer started the new build beside the old one. Fixed and proven by installing 0.3.3 over a running 0.3.0 and starting it three more times.
- **Devices** — an expired connection request now says how to ask again; one that expires while the code is typed shows that instead of a dead Connect; offline devices show when they were last seen (two computers with one name after a reinstall).
